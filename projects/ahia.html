01Overview

A multi-tenant retail platform for small traders, delivered as a backend service, a web application and an offline-first mobile client. The problem is a counter sale: a trader needs to record what left the shelf, what was paid and what is still owed, on a phone, often with no signal.

Every business-owned table carries a row-level security policy that is bound into the transaction, so a query that forgets its tenant filter returns nothing rather than another shop's data.

02How it is built

  • Sales, payments, stock movements, expenses and audit events are append-only ledgers committed together, so a failure part-way through leaves no half-recorded money.
  • Offline devices queue operations and push them through a sync service keyed on an operation identifier, so a retry after a lost reply cannot book the same sale twice.
  • Authorization is deny-by-default: atomic permissions compose into roles, and a caller cannot grant a permission they do not hold themselves.
  • Customers build a list from a public link without an account. The trader prices it, sources what is missing, packs it, and dispatch records the transporter and waybill.
  • Storage and media run behind a provider-neutral port with server-side validation and per-tenant quota accounting that survives concurrent uploads.
  • Roughly two thousand tests, including architecture contracts that fail the build when a layer is imported from the wrong direction.
